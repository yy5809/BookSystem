# Docker 部署 — 原子操作清单

> **适用项目**：RuoYi-Vue 3.9.0（Spring Boot 模块化单体应用）  
> **适用环境**：Windows 11 + Docker Desktop + WSL 2  
> **总步骤数**：34 步  
> **执行方式**：按编号顺序，一步做完再做下一步  

---

## 零、架构说明

### 本项目架构：模块化单体

RuoYi-Vue 是一个**模块化单体应用**，6 个 Maven 模块（`ruoyi-admin`、`ruoyi-common`、`ruoyi-framework`、`ruoyi-system`、`ruoyi-quartz`、`ruoyi-generator`）最终编译为一个 JAR 文件运行。

**当前部署的服务拓扑：**

```
                           Nginx (端口 8081)
                          /                \
                   前端静态文件           反向代理
                  (ruoyi-ui/dist)       /prod-api/ → app:8080
                                           |
                                      Spring Boot (端口 8080)
                                     /                  \
                                MySQL (3306)         Redis (6379)
```

### 如果是微服务架构，部署上的核心差异

| 维度 | 单体（本项目） | 微服务 |
|------|-------------|--------|
| **Dockerfile 数量** | 1 个 | N 个（每个服务一个） |
| **docker-compose 行数** | ~100 行 | 数百行起步 |
| **启动顺序依赖** | app 依赖 MySQL + Redis | 服务间互相依赖，需注册中心协调 |
| **数据卷** | 3 个（MySQL + Redis + 上传文件） | 每个服务的数据库各需独立卷 |
| **配置文件管理** | 硬编码在 application.yml | 需配置中心（Nacos/Apollo） |
| **构建方式** | 一次 `mvn package` | 逐个 `mvn package` 或在 CI 中并行构建 |
| **网关** | Nginx | Spring Cloud Gateway / Zuul / Kong |
| **服务发现** | 无（直接写死地址） | Nacos / Eureka / Consul |

部署微服务时，每一处标注「微服务专属」的步骤都需按 N 个服务重复执行。

## 第一阶段：准备环境

### 第 1 步：以管理员身份打开 PowerShell

```
右键点击「开始」菜单 → Windows PowerShell (管理员) → 是
```

### 第 2 步：启用 WSL 功能

在 PowerShell 中逐条执行：

```powershell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
```

### 第 3 步：重启计算机

```
开始菜单 → 电源 → 重启
```

### 第 4 步：设置 WSL 2 为默认版本

重启后，再次以管理员身份打开 PowerShell，执行：

```powershell
wsl --set-default-version 2
```

> 如果提示需安装内核更新包，浏览器打开 https://aka.ms/wsl2kernel → 下载并安装 → 回到此步继续

### 第 5 步：下载 Docker Desktop 安装程序

```
浏览器打开 https://www.docker.com/products/docker-desktop/
点击 Download for Windows
```

### 第 6 步：安装 Docker Desktop

```
双击 Docker Desktop Installer.exe
勾选 "Use WSL 2 instead of Hyper-V"（必须勾选）
点击 OK → 等待安装完成 → 点击 Close and restart
```

### 第 7 步：验证 Docker 安装

重启后，打开 PowerShell（普通用户即可），执行：

```powershell
docker version
```

确认输出包含 Client 和 Server 两部分（Server 不为空即为正常）。

## 第二阶段：修改项目配置文件

### 第 8 步：打开 PowerShell 并进入项目目录

```powershell
cd D:\USERPROG\JavaEE\RuoYi-Vue
```

### 第 9 步：修改 Redis 连接地址

打开文件 `ruoyi-admin/src/main/resources/application.yml`

找到：

```yaml

```

改为：

```yaml

```

> **微服务专属**：如果你的微服务项目使用了 Redis，每个需要 Redis 的微服务都要做同样的修改。建议将 Redis 地址提取到配置中心统一管理。

### 第 10 步：修改文件上传路径

在同一个 `application.yml` 文件中，找到：

```yaml

```

改为：

```yaml
profile: /home/ruoyi/uploadPath
```

保存并关闭文件。

### 第 11 步：修改数据库连接地址

打开文件 `ruoyi-admin/src/main/resources/application-druid.yml`

找到：

```
jdbc:mysql://localhost:3306/ry-vue
```

改为：

```
jdbc:mysql://mysql:3306/ry-vue
```

保存并关闭文件。

> **微服务专属**：微服务架构通常每个服务有独立的数据库（Database per Service pattern），需要为每个服务分别修改数据源配置，并且数据库名不能重复。

## 第五阶段：创建部署文件

### 第 19 步：创建 Dockerfile

> **微服务专属**：有几个微服务，就要创建几个 Dockerfile。建议统一放到各服务目录下，如 `user-service/Dockerfile`、`order-service/Dockerfile`。

在项目根目录创建文件 `Dockerfile`，内容如下：

```dockerfile
# 基于 Ubuntu 20.04 LTS (Focal) 的 JDK 8 镜像
# 使用 Focal 而非 Alpine，因为 Alpine 缺少 Kaptcha 验证码所需的字体库
FROM eclipse-temurin:8-jre-focal
ENV TZ=Asia/Shanghai
RUN ln -snf /usr/share/zoneinfo/$TZ /etc/localtime && echo $TZ > /etc/timezone
WORKDIR /app
RUN mkdir -p /home/ruoyi/uploadPath
COPY ruoyi-admin/target/ruoyi-admin.jar app.jar
COPY sql/ry-vue.sql /app/sql/ry-vue.sql
EXPOSE 8080
ENV JAVA_OPTS="-Xms256m -Xmx1024m -XX:MetaspaceSize=128m -XX:MaxMetaspaceSize=512m"
ENV SPRING_PROFILES_ACTIVE=druid
ENTRYPOINT java ${JAVA_OPTS} -Dfile.encoding=UTF-8 -jar app.jar
```

### 第 20 步：创建 docker-compose.yml

> **微服务专属**：微服务架构的 docker-compose.yml 要长得多——每个服务一个 service 块，外加注册中心（Nacos/Eureka）、配置中心、网关、链路追踪等基础设施服务。

在项目根目录创建文件 `docker-compose.yml`，内容如下：

```yaml
services:

  mysql:
    image: mysql:8.0
    container_name: ruoyi-mysql
    restart: unless-stopped
    networks:
      - ruoyi-network
    ports:
      - "3307:3306"
    volumes:
      - mysql_data:/var/lib/mysql
      - ./sql/ry-vue.sql:/docker-entrypoint-initdb.d/01-init-ry-vue.sql
    environment:
      MYSQL_ROOT_PASSWORD: 12345678
      MYSQL_DATABASE: ry-vue
      TZ: Asia/Shanghai
    command:
      - --character-set-server=utf8mb4
      # MySQL 8.0.46+ 要求 utf8mb4 使用 utf8mb4_general_ci，不能使用 utf8_general_ci
      - --collation-server=utf8mb4_general_ci
      - --default-time-zone=+8:00
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-u", "root", "-p12345678"]
      interval: 10s
      timeout: 5s
      retries: 10
      start_period: 60s

  redis:
    image: redis:7-alpine
    container_name: ruoyi-redis
    restart: unless-stopped
    networks:
      - ruoyi-network
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
    command:
      - redis-server
      - --save 60 1
      - --appendonly yes
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 3s
      retries: 5

  app:
    build:
      context: .
      dockerfile: Dockerfile
    image: ruoyi-vue-app:latest
    container_name: ruoyi-app
    restart: unless-stopped
    networks:
      - ruoyi-network
    ports:
      - "8080:8080"
    volumes:
      - ruoyi_upload:/home/ruoyi/uploadPath
    environment:
      DB_PASSWORD: "12345678"
      TZ: Asia/Shanghai
      SPRING_PROFILES_ACTIVE: druid
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_healthy

  nginx:
    image: nginx:alpine
    container_name: ruoyi-nginx
    restart: unless-stopped
    networks:
      - ruoyi-network
    ports:
      - "8081:80"
    volumes:
      - ./docker/nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./ruoyi-ui/dist:/usr/share/nginx/html:ro
    depends_on:
      - app

networks:
  ruoyi-network:
    driver: bridge

volumes:
  mysql_data:
    driver: local
  redis_data:
    driver: local
  ruoyi_upload:
    driver: local
```

### 第 21 步：创建 Nginx 配置文件

创建目录结构：

```powershell
mkdir docker\nginx
```

在 `docker/nginx/nginx.conf` 中写入：

```nginx
worker_processes  2;

events {
    worker_connections  1024;
}

http {
    include       mime.types;
    default_type  application/octet-stream;
    sendfile      on;
    keepalive_timeout  65;

    gzip on;
    gzip_min_length 1k;
    gzip_comp_level 6;
    gzip_types text/plain application/javascript application/x-javascript text/css application/xml text/javascript image/svg+xml;
    gzip_vary on;

    server {
        listen       80;
        server_name  localhost;

        location / {
            root   /usr/share/nginx/html;
            index  index.html index.htm;
            try_files $uri $uri/ /index.html;
        }

        location /prod-api/ {
            proxy_set_header Host $http_host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_pass http://app:8080/;
        }
    }
}
```

```
双击桌面 Docker Desktop 图标
等待右下角鲸鱼图标不再闪烁（约 30 秒~2 分钟）
```

### 第 24 步：打开 PowerShell 进入项目目录

```powershell
cd D:\USERPROG\JavaEE\RuoYi-Vue
```

### 第 25 步：首次部署 — 构建镜像并启动

```powershell
docker compose up -d --build
```

**命令含义：**
- `up` — 创建并启动所有服务
- `-d` — 后台运行
- `--build` — 强制重新构建镜像，确保 Dockerfile 修改生效

**首次部署执行过程：**
1. 拉取 `mysql:8.0` 和 `redis:7-alpine` 基础镜像（约 1~3 分钟，取决于网速）
2. 构建应用镜像（基于 `eclipse-temurin:8-jre-focal`，约 30~60 秒）
3. 拉取 `nginx:alpine` 镜像
4. 创建网络和卷
5. 按依赖顺序启动容器：mysql → redis → app → nginx
6. MySQL 首次启动时会自动执行 `sql/ry-vue.sql` 完成建表和数据初始化

**预期输出：**

```
[+] Building 35.2s (9/9) FINISHED
[+] Running 5/5
 ✔ Network ruoyi-network  Created
 ✔ Container ruoyi-mysql  Started
 ✔ Container ruoyi-redis  Started
 ✔ Container ruoyi-app    Started
 ✔ Container ruoyi-nginx  Started
```

> **微服务专属**：首次部署可能要启动 10~30 个容器，拉取镜像和构建的时间会显著增加。建议结合 `docker compose build --parallel` 并行构建。

### 第 26 步：确认所有容器正常运行

```powershell
docker compose ps
```

确认所有容器 `STATUS` 列显示 `Up`，MySQL 和 Redis 显示 `(healthy)`：

```
NAME                IMAGE                         STATUS                    PORTS
ruoyi-mysql         mysql:8.0                      Up (healthy)              0.0.0.0:3307->3306/tcp
ruoyi-redis         redis:7-alpine                 Up (healthy)              0.0.0.0:6379->6379/tcp
ruoyi-app           ruoyi-vue-app:latest           Up                        0.0.0.0:8080->8080/tcp
ruoyi-nginx         nginx:alpine                   Up                        0.0.0.0:8081->80/tcp
```

### 后续重新部署（修改代码后）

```powershell
# 停掉当前容器
docker compose down

# 重新构建（--build 确保使用最新的 JAR 包和 Dockerfile）并启动
docker compose up -d --build
```

> 如果只修改了配置、没有改代码（如 docker-compose.yml），可以不用 `--build`，直接 `docker compose up -d` 即可。

### 常用命令

| 场景 | 命令 |
|------|------|
| 首次部署 | `docker compose up -d --build` |
| 修改代码后重部署 | `docker compose up -d --build` |
| 仅修改配置后重部署 | `docker compose up -d` |
| 停止所有服务（保留数据） | `docker compose down` |
| 停止并清理数据卷 | `docker compose down -v` |
| 重启单个服务 | `docker compose restart <服务名>` |
| 查看实时日志 | `docker compose logs -f` |
| 查看指定服务日志 | `docker compose logs --tail=50 app` |
| 查看 Nginx 日志 | `docker compose logs --tail=20 nginx` |

## 第八阶段：常见问题处理

### 第 33 步：端口冲突

**现象**：`docker compose up -d` 报错 `port is already allocated`。

**原因**：本机已运行 MySQL（3306）或其他程序占用了端口。

**解决方案**：

修改 `docker-compose.yml` 中的外部端口映射：

```yaml
  mysql:
    ports:
      - "3307:3306"    # 本机用 3307，Docker 内部还是 3306
  nginx:
    ports:
      - "8081:80"      # 本机用 8081，Docker 内部还是 80
```

### 第 34 步：MySQL 启动失败 — collation 错误

**现象**：日志显示 `COLLATION 'utf8_general_ci' is not valid for CHARACTER SET 'utf8mb4'`。

**原因**：MySQL 8.0.46+ 不再支持 `utf8mb4` 搭配 `utf8_general_ci`。

**修复**：将 `docker-compose.yml` 中的 collation 改为：

```yaml
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_general_ci    # 原来是 utf8_general_ci
```

修改后需删除旧数据卷再启动：

```powershell
docker compose down
docker volume rm ruoyi-vue_mysql_data
docker compose up -d
```

### 第 35 步：验证码接口报 500 — 字体缺失

**现象**：`/captchaImage` 返回 500，日志显示 `NoClassDefFoundError: X11FontManager`。

**原因**：基于 Alpine Linux 的 JDK 镜像缺少字体库，Kaptcha 验证码组件无法渲染图片。

**修复**：将 Dockerfile 的基础镜像从 `eclipse-temurin:8-jre-alpine` 改为 `eclipse-temurin:8-jre-focal`（Ubuntu 基底，自带字体）：

```dockerfile
FROM eclipse-temurin:8-jre-focal
```

### 第 36 步：重建镜像时修改不生效

**现象**：改了 Dockerfile 或重新打包了 JAR，但容器启动后还是旧代码。

**原因**：Docker 使用了缓存（cache）。

**修复**：始终使用 `--build` 参数：

```powershell
docker compose up -d --build
```

## 附录：微服务部署清单速查

当你要从本项目（单体）扩展到微服务架构时，需要在以下位置做乘法：

| # | 事项 | 单体（本项目） | 微服务 |
|---|------|-------------|--------|
| 1 | Dockerfile 数量 | 1 个 | N 个（每个服务一个） |
| 2 | JAR 包数量 | 1 个 | N 个 |
| 3 | docker-compose service 数 | 4 个 | 10~30+ 个 |
| 4 | 数据库 | 1 个 MySQL 实例 | 通常多个 MySQL 实例或同一实例多个库 |
| 5 | application.yml 修改 | 改 1 份 | 每服务改 1 份 |
| 6 | 启动依赖 | app 依赖 MySQL + Redis | 服务间互相依赖，需注册中心 |
| 7 | 前端代理目标 | `http://app:8080` | `http://gateway:8080` |
| 8 | 健康检查 | MySQL + Redis | 每个服务 + 基础设施 |
| 9 | 构建时间 | ~2 分钟 | 10~30 分钟（可并行） |
| 10 | 调试方式 | `logs app` | `logs <service-name>` 逐个排查 |
